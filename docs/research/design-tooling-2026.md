- The video: oEmbed confirms the title "Github #1 Trending Skill's Author Just Fixed Claude's Design Problem" and the channel AI LABS ([channel](https://www.youtube.com/@AILABS-393)). The page, description and transcript could not be read, and the channel page redirects to a consent wall. Which skill the video covers is not confirmed.
- Best candidate: Impeccable, [pbakaus/impeccable](https://github.com/pbakaus/impeccable) by Paul Bakaus (ex-Google, creator of jQuery UI), Apache 2.0, 86.1k stars at fetch time. Search results show two other YouTube videos about it ([1](https://www.youtube.com/watch?v=r2P1v64pM28), [2](https://www.youtube.com/watch?v=GDB6ATIPo4E)), but neither is verified as AI LABS, and the repo README does not mention GitHub trending. Reasons it fits: a single author who "fixed Claude's design problem", very high stars, and the README says it started from Anthropic's frontend-design skill. Treat the match as probable, not proven.
- What it does (README, fetched 2026-10-24): one skill, 24 `/impeccable` commands (`craft`, `audit`, `polish`, `critique`, `harden` and more), 62 deterministic detector rules for AI-frontend tells (Inter everywhere, purple-blue gradients, nested cards, gradient text, side-stripe borders, glassmorphism), live browser iteration, and `/impeccable init` which writes a `PRODUCT.md` of durable product context.
- Install: `npx impeccable install` (recommended), `npx impeccable update`, a git submodule via `npx impeccable link`, a Claude Code plugin (`/plugin marketplace add pbakaus/impeccable`), a ZIP from impeccable.style, or a manual copy. A secondary source dated 2026-10-19 lists version 4.7.0 ([skillselion](https://skillselion.com/skills/pbakaus/impeccable)).
- Overlap with the local `frontend-design`: both attack AI tells (the local §3 list already bans Inter, purple gradients, glassmorphism, gradient text, pill buttons) and both write a project design doc (`design/design.md` versus `PRODUCT.md`). Impeccable adds what the local skill lacks: an automatic post-edit detector hook, a command vocabulary for later polish rounds, and live in-browser iteration. The local skill adds what Impeccable lacks: the stack binding (Tailwind v4 `@theme inline`, Base UI, Motion/GSAP/R3F), dembrandt token capture, motion rules, and the Playwright verify loop with its reviewer brief.
- Security (README): the skill runs a launcher around a bundled engine binary, downloaded once to `~/.impeccable/bin/` if missing. It calls the impeccable.style roll API at the start of every new design round, and unless opted out it also sends an anonymous record of which options were shown and chosen (README says no code, file or project names). Opt out with `npx impeccable telemetry off`, `DO_NOT_TRACK=1` or `IMPECCABLE_NO_TELEMETRY=1`; the roll request still happens when opted out. The installer adds a hook that runs the detector after UI file edits, and Claude Code hooks run regardless of tool approval. Live mode starts a localhost server and can run a `package.json` script (`impeccable:manual-edit-validate`) in a shell. The `detect` command can drive a local Chrome against a URL.
- Default taken 2026-10-24 (owner may overrule): port the rules only, install nothing. Two skills with overlapping bans and different doc files (`design.md` versus `PRODUCT.md`) compete for context, and the hook plus telemetry put third-party code on every edit. Ideas to borrow into the local skill: the tell list (compare its 62 rules against §3 Look and add what is missing), a `critique`/`polish` pass vocabulary, and a one-file product-context doc. The rules live in the repo and were not read this run, so the port starts by reading them on GitHub, not by running the package.

## Google Stitch as of 2026-10-24

- Product state: Stitch is a Google Labs tool at [stitch.withgoogle.com](https://stitch.withgoogle.com/). The [18 Mar 2026 "vibe design" post](https://blog.google/innovation-and-ai/models-and-research/google-labs/stitch-ai-ui-design/) added an AI-native infinite canvas that takes images, text or code as context, a design agent with an agent manager for parallel ideas, voice critique, interactive prototypes with a Play button, auto-generated next screens, URL-to-design-system extraction, DESIGN.md import and export, and an MCP server plus SDK. The [19 May 2026 I/O post](https://blog.google/innovation-and-ai/models-and-research/google-labs/stitch-updates/) added real-time streaming by the Stitch Agent, steering mid-generation, a shareable link via AI Studio, export to Antigravity, and publishing to the web with Netlify.
- Limits: neither Google post states limits or pricing. Third-party guides say 350 Standard and 200 Experimental generations per month, with Pro raised from 50 to 200 in March 2026, and models switchable between Gemini 3.0 Pro/Flash and 2.5 Pro/Flash ([search summary of almcorp, nxcode and others](https://almcorp.com/blog/google-stitch-complete-guide-ai-ui-design-tool-2026/)). One source reports 400 daily credits in April 2026 instead, so the numbers conflict; check the app itself.
- Prompting that works: Google's only first-party prompt guide is a forum thread from May to June 2025 ([Stitch prompt guide](https://discuss.ai.google.dev/t/stitch-prompt-guide/83844), linked from the official [llms.txt](https://stitch.withgoogle.com/llms.txt)). Its advice: start broad, then go screen by screen; set the vibe with adjectives (they drive colour, type and imagery); plain language, no JSON or XML; one or two changes per prompt, naming the target ("primary button on sign-up form"); use UI terms (navigation bar, card layout); state whether images and icons should follow a theme change; keep prompts under about 5,000 characters since longer ones drop components; save a screenshot after each good step. Community reports in that thread say the first result lands near 60% of intent. It predates the canvas and DESIGN.md, so it covers per-screen prompting only.
- Design-system-first (inference from the DESIGN.md design, not a Google instruction): write or extract a DESIGN.md first, import it into the project, then prompt per screen. The Google Labs `enhance-prompt` skill rewrites a rough idea into a Stitch-style prompt.
- Consistency across screens: DESIGN.md is the intended carrier ("move a design system to a different Stitch project", 18 Mar post). Third-party tips: Shift-click several screens and apply a theme change to all at once; vague prompts give generic, similar layouts, especially in Flash mode ([search summary](https://tech-insider.org/google-stitch-ai-design-tool-march-2026-update/)). A competitor's page claims the same prompt gives different results each time ([designless.io](https://designless.io/google-stitch-limitations), marketing, unverified). The `stitch-loop` skill generates multi-page sites.
- Export: ZIP with HTML files, PNG screenshots and a DESIGN.md; targets for AI Studio, Figma ("Copy to Figma" keeps layers and Auto Layout), Jules, MCP and clipboard (secondary sources: [pillitteri.it](https://pasqualepillitteri.it/en/news/647/google-stitch-mcp-export-claude-code-design-to-code), search summary). Google's posts confirm only AI Studio, Antigravity, Netlify, DESIGN.md, MCP and SDK. Whether Figma export works in Experimental mode is unconfirmed.
- MCP and API: the remote server is `https://stitch.googleapis.com/mcp`, added in Claude Code with an API key header, per a third-party tutorial: `claude mcp add stitch --transport http https://stitch.googleapis.com/mcp --header "X-Goog-Api-Key: <key>" -s user`. A community proxy `@_davideast/stitch-mcp` uses gcloud credentials instead. Keep the key in a dotenvx-managed file, never inline. Not used on this map: the owner generates in Stitch by hand.
- Official skills: [google-labs-code/stitch-skills](https://github.com/google-labs-code/stitch-skills) (Apache 2.0, 8.6k stars, 98 commits, "not an officially supported Google product"). Plugins: `stitch-design` (generate-design, manage-design-system, extract-design-md, code-to-design), `stitch-build` (react-components, shadcn-ui, react-native, remotion), `stitch-utilities` (design-md, enhance-prompt, stitch-loop, taste-design). Install for Claude Code: `npx plugins add google-labs-code/stitch-skills --scope project --target claude-code`, or per skill with `npx skills add google-labs-code/stitch-skills --skill design-md`.
- Security of stitch-skills: skills carry `scripts/` folders ("executable enforcers", validation and networking). `react-components` fetches the screen with a system `curl` to Google Cloud Storage and validates output with an `@swc/core` AST check for hardcoded hex values; `shadcn-ui` ships `scripts/verify-setup.sh` and calls `npx shadcn@latest`. Read each script before use and pin a commit, not `main`.

## Stitch output to this stack (Next.js, Tailwind 4, shadcn / Base UI)

- Known path (inference from the sources above, not a documented recipe): export the ZIP; generate or export DESIGN.md; treat the exported HTML as a visual reference only; feed DESIGN.md plus PNGs to the local `frontend-design` skill, which already turns a design doc into `:root` CSS variables mapped through `@theme inline`; rebuild components from Base UI primitives restyled to those tokens; then run the skill's §5 Playwright verify against the Stitch PNGs.
- The `react-components` skill targets Atomic-Design React with a `style-guide.json`; its README never mentions Tailwind or Base UI, so its output would need a port to Tailwind v4 tokens. The `shadcn-ui` skill is generic shadcn guidance and its README does not describe reading a Stitch screen.
- Fit with the existing flow: DESIGN.md from Stitch seeds the new repo's design doc (the local §2 table: palette with contrast, type, spacing, motion, references). Stitch has no motion tokens, so motion stays the local skill's job, informed by [motion-portfolio-2026.md](motion-portfolio-2026.md).

## Applied to this site

- Write Stitch prompts in two passes: one design-system prompt (adjectives for mood, palette intent, type direction, no layout), then one prompt per screen with one or two changes each, under 5,000 characters. Export DESIGN.md after the first screen looks right and import it into each later screen's project.
- Keep Stitch output as reference and rebuild in code with `frontend-design`. The look is a full redesign (owner's decision, 2026-10-24); the old site's look is not a constraint.
- Impeccable: install nothing. Port its detector rules into `frontend-design` §3 Look by reading them on GitHub and adding the ones the local list lacks.
- `stitch-skills`: not needed while the owner generates by hand; if ever used, only `design-md` and `enhance-prompt`, pinned to a commit after reading their scripts.
