## Patterns and decisions

The work is split into three stages, cheapest first. A Python stage with no dependencies and no model collects postings and decides everything that code can decide. A cheaper model reads only the prose pages, such as career pages and digest articles. The strongest model does judgment only: scoring, the daily digest and the direction of the research.

Inside the judgment stage, company research and letters go to one mid-tier helper per company, and closure page checks go to the cheapest model. A run is started by hand, as a daily run or as a backfill that rescores old entries. The model step has a timeout five minutes shorter than its job, so the upload steps still run. The data store is the repository itself, and a checkpoint commit after scoring means a crash in research loses only research.

The board is a Next.js app behind one shared password. Each vacancy record is validated with Zod on its own, so one malformed record from an unattended model run is dropped and counted in a banner instead of failing the build. Statuses live in a private Vercel Blob, so the phone and the desktop agree. The screen updates at once and saves behind the tap, and a failed save raises an error toast, because a status that looks saved and is not could cost a real application.

## Cases

**Closing a vacancy only when it can be proven.** Wrongly hiding a live job costs a real chance, so the code may say "closed" and never "open". A studio vacancy closes when it is missing from a fresh board snapshot that came back with rows. An empty or unreadable snapshot closes nothing. For the regional job board, I read the page's own archived flag from its structured data, because the word "archived" sits in the text of every page and a plain text search would have closed the whole board. A missing page closes. A refusal or a legal block says nothing. An empty board means unknown. Closed postings stay for history and sink to the bottom of the list.

**Parsers that fail silently, backed by tests that fail loudly.** When a site changes its markup, a pattern matches nothing and the source reports zero postings, which looks like a quiet day. I saved real pages from each source and wrote tests on what must stay true: rows are found, titles are not empty, and the role filter keeps design roles while dropping engineering roles tagged technical design. A markup change now breaks the test run instead of quietly emptying the board.

**Two scores that cannot disagree, and arguments that can be checked.** One ranking number mixes "do I want this job" with "would the employer hire me", so a dream job out of reach and an easy job nobody wants look alike. I made two independent numbers, interest and chance, and hiring-odds penalties never touch interest. Each vacancy gets up to three "why try" lines of three allowed kinds: a skill overlap, a stop signal that is not real, or the real cost of applying. Each can be checked against the same card. Praise, predictions and exclamation marks are forbidden, and an empty list is the correct answer when nothing follows from the data.

**Deduplication in two halves, with ids the model cannot invent.** The same job appears on a studio page, a regional board and a channel post under different spellings. Code does the exact half: it strips tracking parameters from links, builds a company-plus-title id and stamps it on every new posting. The model is ordered to use that id verbatim, because a model writing the data file used to make up its own. The model does the judgment half. Same company and same role means one vacancy, so it enriches the existing entry with a salary, a contact or fuller text and prefers the studio's own apply link.
