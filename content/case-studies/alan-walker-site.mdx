## Patterns and decisions

- The shop code ships in the repo: product, collection, search and cart pages, filters, bundles and the cart store. A permanent redirect sends every shop route to the brand store.
- The site has no database and no CMS. Product data comes from the Shopify Storefront GraphQL API, with types generated by GraphQL Codegen. Tour dates come from the Bandsintown API. Copy lives in one next-intl message file and in typed constants.
- Next.js builds a standalone output with the React Compiler on. Every page lives under a locale segment and the URL always carries the prefix. The site has 30+ routes: 22 pages and 10 route handlers.
- oRPC holds the API: 16 procedures, 15 of them for the shop. A server-side client and a browser client share the same router, and TanStack Query handles the browser side.
- Every shop procedure is built on one Shopify middleware. Handlers stay thin and read the buyer's country and language from the context, and the cart handlers also read the buyer IP.
- State has three homes. Zustand keeps the cart, nuqs keeps filters and sort in the URL, and React Hook Form with Zod runs the forms. A filtered list survives a reload and can be shared.
- Newsletter sign-up is a next-safe-action server action with Zod validation and a rate limit by IP. Env is validated with T3 Env.
- The home page has 15 scroll sections. Each one has its own GSAP timeline, and Lenis smooth scroll is kept in step with ScrollTrigger. The last section is a canvas starfield with 170 stars on desktop and 120 on mobile, driven by wheel velocity with friction.
- The tour fetch revalidates hourly. On an error it returns a fallback, so the page renders an empty list.
- The sitemap is built from live Shopify data: up to 250 products and 50 collections next to the static routes.
- I built the UI from a given design, with 35+ UI components.

## Cases

**A market chosen from the request.** Prices, currency and availability change by country, and a first visit carries no choice from the user. I wrote one middleware that resolves the country in a fixed order: a stored cookie, a query parameter, six edge or custom headers, the region of the browser language, then Germany. Names and aliases such as USA, UK and South Korea become ISO codes. Language follows the same idea and defaults to English. The buyer IP is taken from the first valid value among eight candidate headers and sent to Shopify on cart calls. All 15 shop procedures use the middleware, so no handler repeats the logic.

**A cart that answers at once and stays the Shopify cart.** A click on add or quantity should not wait for Shopify, and checkout has to run on the real Shopify cart. The Zustand store applies each change locally and schedules a sync after 800 ms. It saves only the lines, the cart id and the checkout URL. A single sync procedure compares the local lines with the server cart by variant. It sends removals, then quantity updates, then additions. An empty local cart clears the server lines, and a missing cart or one older than 10 days is created again. On reload the store rehydrates and syncs, and the server line ids are written back.

**Delivery with Kubernetes and Cloudflare Tunnel.** The site ships as a container. Every pull request needed a preview to review, and production had to roll out without downtime. A workflow builds a Docker image tagged with the PR number and short commit hash. It generates a Kustomize overlay with its own host, retries the apply up to 5 times with a growing delay, waits for the rollout and comments the preview URL on the PR. A concurrency group per PR cancels stale runs, and cleanup removes the environment on close. Production deploys on push to main. Readiness and liveness probes and zero unavailable pods keep the rollout whole, and production runs 3 replicas. Traffic enters through two Cloudflare Tunnel replicas, and the Infisical operator syncs the secrets. I wrote the setup docs for both.
