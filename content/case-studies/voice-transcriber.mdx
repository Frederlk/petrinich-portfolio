## Patterns and decisions

- The transcriber runs on my own machine. Whisper runs through faster-whisper on the graphics card in half precision, with a warm-up pass, and falls back to the processor with a smaller number format when no card is found.
- The web page is served by a standard library HTTP server in Python, with one background worker thread and a queue. I used no framework.
- Formatting is a set of pure functions: paragraphs split on pauses of two seconds or more, a timecode on each paragraph, and the recording date read from the file name in two date formats, with the file modification time as the last resort. Tests cover them, including Cyrillic file names and titles.
- The long-recording pipeline works in stages: audio extraction with FFmpeg, a Whisper stage with word timings and confidence, speaker turns from a diarization model, then a merge that writes text with speaker labels, subtitles and a cache file.

## Cases

**Speaker labels from one microphone.** A table-top game session recorded by a single room microphone makes raw speaker detection shatter into short turns, and assigning words to them flips the speaker in the middle of a sentence. I clean the turns before any word is assigned: turns of the same speaker that sit close together merge, and slivers drop. Each word takes the speaker with the longest overlap, a word that falls in a gap takes the nearest turn, and a smoothing pass absorbs flips of one or two words unless a real pause or a real handover sits beside them. Whisper confidence does not track correctness, so I mark doubt in layers. Segment checks catch gross failures such as text over silence and repetition loops. Weak words get an inline mark, and a paragraph with many weak words gets a mark at its start. A held vowel looped into hundreds of characters is collapsed and flagged, and a real hole in the audio shows as an ellipsis. An unmarked passage is not a verified one.

**Re-runs that protect hand edits.** Transcribing a long recording takes a while, and tuning a threshold must not mean transcribing again. Both model stages write one cache file, and it is written last, so an interrupted run never leaves a cache that claims to be complete. A re-run only re-renders from the cache, and the video becomes optional once the cache exists. Subtitles get corrected by hand, so before writing, the script compares the file on disk with what it would produce. A file that differs moves to an edited copy and is not overwritten. The two model stages also live in two Python environments on purpose. The Whisper runtime and the PyTorch runtime ship conflicting CUDA libraries, and both models together would not fit on an 8 GB card. Whisper runs as a subprocess in its own environment, and the models run one after the other.

**A local page with a queue.** I wanted to drop in a batch of voice memos and leave. The page lists the chosen audio files, shows progress for each, and saves a timestamped text file next to every source. The native file dialog opens in a subprocess. On Windows that subprocess printed Cyrillic paths in the ANSI code page and died, so picked files never reached the queue. I forced UTF-8 for the child process and added regression tests with Cyrillic paths, titles and dates.

**Titles and hotwords.** Each transcript gets a title in its file name. When the Claude Code command-line tool is installed, it writes the title, and otherwise the first words of the transcript stand in. For names that Whisper garbles, a plain-text hotword list biases the decoder, with separate lists per context. The decoder silently truncates a long list, so I trimmed each list to the names the model actually gets wrong, and kept a snippet that measures a list before more names go in.
