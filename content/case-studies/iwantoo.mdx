## Patterns and decisions

- I built the whole site alone, front end and content layer. It is Next.js with the App Router, React and TypeScript, styled with Tailwind CSS. Pages are server components, and interactivity sits in small client components.
- Case content lives in Sanity, read through the Sanity client with one query per need and types generated from the schema. The Sanity Studio is mounted inside the same app, so editors work on the site's own domain.
- Forms use Zod schemas and React Hook Form. A small typed hook keeps input and output types apart, and the fields are thin wrappers for text, auto-growing text, checkbox groups, radio groups and a date picker.
- Environment variables are validated with T3 Env, with a skip flag for CI. React Compiler is on, and a GitHub Actions job lints and typechecks every push, so the deploy build stays quick.
- Images go through the framework image component, and every placement has its own sizes string. Router cache times are tuned for dynamic and static pages.

## Cases

**A cursor ripple that only runs where it pays off.** Every large image had to react to the cursor like water. A WebGL canvas per image is heavy on a page with a dozen of them, and useless on a phone. I rendered the plain image first and mounted a small WebGL scene on top only when the image sat well inside the viewport. Once mounted, it stayed. Phone-width screens skip it, and the pixel ratio is capped at 1. Brush sprites come from a pool of 100 that fade, spin and grow, so nothing is created on a mouse move. The brushes are drawn into an offscreen target, and a hand-written fragment shader uses it as a displacement map to bend the image along the stroke. The distortion trails the cursor and fades out, for images that crop to fill and for images that fit whole.

**Route changes through a curtain.** The App Router swaps pages instantly, which did not suit a studio site with a strong look. I wrapped internal links so a click is intercepted. A click on the current page does nothing. Otherwise a two-layer curtain restarts and slides up. When it covers the screen, the route is pushed and the curtain slides away. A white cover hides the first paint on load. Every internal link on the site goes through this wrapper, so the effect is consistent without any page knowing about it.

**A CMS that editors can preview from inside.** Studio staff needed to add case studies and see them in the real layout before publishing. The Studio opens the site in a side frame through its Presentation tool. A signed preview address is checked on the enable route, and draft mode turns on. One fetch wrapper switches three things by mode. Published content is cached for a minute, or until a tag is invalidated. Drafts use the draft perspective with a read token and are never cached. Edit overlays are encoded into the text only on preview deployments. An editor can click any text in the frame and jump to its field. The preview button and the overlays are not part of the normal production layout.

**A cooperation request that lives in the URL.** The long request form has to open from the header, from each service row and from the contact page, without passing state between them. I kept the dialog state in a query parameter with nuqs. Opening pushes a history entry and closing clears the parameter, so any link can open the form and the back button closes it. The form has seven numbered questions: name, email, work types, budget range, details, start date and deadline. Start dates in the past are rejected by the schema and shown disabled in the calendar. Errors appear inside the question label, and a confirmation dialog follows a valid submit.
