## Patterns and decisions

The toolbox has 8 commands and runs straight from a Git repository through pnpm dlx, with no registry and no build step. It is plain JavaScript on Node.js with zero dependencies: only built-in modules.

One entry point forwards to the matching command and discovers every command in the folder by itself. The help line comes from the first comment of each file, so a new codemod shows up the moment it lands. A single entry point also works around pnpm dlx failing to expose extra binaries on Windows.

The main codemods share one shape: a pure function that takes source and returns nothing when there is nothing to change, wrapped in a thin command line. The command lists the files it would touch and asks for confirmation, or applies with a yes flag, or only prints with a dry run flag. A dry run exits with a failure when changes are pending, so it works as a CI check. Without a terminal the command refuses instead of hanging. The tests for those transforms run each one twice, and the second run must change nothing.

## Cases

**Tidying secret files without showing a secret.** Env files collect whatever order things were pasted in, and cleaning one by hand means opening a file full of secrets. A variable added in one place silently missed the other files. I made the layout and the expected key set come from the project's env schema, and made the guarantee about the output. The command prints only key names, counts and section titles. Values are copied byte for byte from the right of the first equals sign, so quotes, a hash inside a value, multi-line values and encrypted blobs survive. A rewrite is refused if it would change the set of keys, and the file stays untouched. Anything outside the schema moves to its own section instead of being dropped. The schema is a TypeScript file, and importing it would run project code, so I read it as text.

**Collapsing comments without touching code.** Hard-wrapped comments fight editors that wrap softly, but a naive regex also rewrites comment markers inside strings, URLs, JSX and regex character classes, and it flattens lists and commented-out code. I wrote a small scanner by hand, with no dependencies, that walks the source and yields comment spans while skipping strings, template literals and regex literals. It decides whether a slash starts a regex from the previous significant token. Block comments and runs of adjacent line comments become one line, and prose JSDoc without tags becomes one line comment per paragraph. Linter and compiler directives are never moved. A comment with a list, a table, a banner, a fenced block, commented-out code or a deeper-indented usage block stays whole. When the scanner misreads a regex, the worst outcome is a skipped comment, never damaged code.

**A lint gap for the React Compiler.** The lint setups on our projects have no rule that flags libraries the React Compiler cannot cache safely, such as TanStack Table, TanStack Virtual and React Hook Form, so UI that silently stops updating reached review. I wrote a guard that looks for value imports, hook calls and method calls against a rule list. Type-only imports are excluded, and a file that already carries the opt-out directive is skipped. The rules are split into enforced and advisory. Seven built-in rules cover it: 4 fail CI, and 3 only warn, for MobX, Zustand and TanStack Query, which are probably safe and stay on a watch list. Each rule carries its reason and links to the upstream issues, printed with the failure, and a project can replace the whole list with its own config file.
